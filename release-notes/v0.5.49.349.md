* Fix pull-to-refresh self-cancellation killing the feed

Root cause: SwiftUI cancels the .refreshable operation task when the
scroll view hierarchy updates during the gesture, and the cancellation
propagated into the in-flight URLSession requests (NSURLError -999
within ~3ms of launch), aborting the web rcmd fetch and every fallback
behind it. Combined with load() clearing the rows up-front, one pull
left the feed permanently empty until relaunch — matching the reported
'cannot refresh' and 'cannot load videos' on device.

- refreshable now kicks the fetch off in an unstructured Task so the
  network load is detached from the refresh control's lifetime
- pass preservingExistingContent: true so the current rows stay on
  screen while the new batch loads (standard Apple behavior)
- add recommendation diagLog entries for rcmd failure/empty paths
  (failures were previously invisible outside bpLog)

Verified on iPhone 17 sim: pull-to-refresh now returns a fresh
18-item batch (Web RCMD API success) instead of wiping the feed.

* Fix video downloads end-to-end

Chain of four bugs made every download useless:

- Background URLSession: the iOS background-session daemon
  rejects byte-range download tasks instantly (NSURLErrorDomain
  -1 'unknown error') on device and simulator. Switch to a
  foreground session — trade-off: downloads pause when the app
  is suspended.
- Infinite retry storm: retry budget was keyed by the ephemeral
  task identifier, but every retry gets a fresh identifier, so
  the budget reset each attempt (67k retries in 2 minutes).
  Now keyed by stable segment identity.
- Merge always failed: FileHandle(forWritingTo:) was called
  without creating the temp file first, so downloads were
  stored unmerged and unplayable.
- CDN error pages accepted as media: a 403 'Access Denied'
  HTML response arrives with no transport error and was
  written into video.media. Responses are now status-validated
  and failed segments retry against the playurl backup CDN
  hosts.

Also: launch-time migration retroactively merges existing
legacy 4-file downloads so previously-broken downloads become
playable without re-downloading.

Verified in simulator: failover path exercised (akamai 403 ->
cosov backup), fresh download plays with non-zero timeline,
migrated legacy download plays.
