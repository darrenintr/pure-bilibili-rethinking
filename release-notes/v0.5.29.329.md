estimate prefetch target size from bandwidth and duration


Build 329 build failed: BiliDashSource.Track has no member
named size. The PlaybackPrefetchManager.runPrefetch started
diagLog I added in the previous commit referenced
playback.dash?.video.size and playback.dash?.audio?.size,
which do not exist on the BiliDashSource.Track struct.

B站 playurl publishes bandwidth (bps) and total duration
(seconds) per track but never the absolute file size - the
real Content-Length only becomes known after the upstream
HEAD/Range request returns. So estimate the prefetch target
as Int64(bandwidth) * Int64(totalDuration) / 8 (within plus
or minus 5 percent for any real video) and also log the raw
bandwidth and totalDuration so the reader can recompute.
Both fields default to 0 when dash is nil, which preserves
the entry log behavior on the missing-dash path.

This unblocks CI for the v0.5.29.329 build that needs the
runPrefetch started and committed diagLog entries to
diagnose the playback stall.
